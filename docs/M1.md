# Cello M1 Plan

* **Author:** Lucas N. Munhoz
* **Date:** 2026-11-14
* **Status:** Ready to build. Closes the M1 blockers from the readiness review (see SPEC.md, "Settled in review").

## What M1 delivers

A local board you can use by hand: workspaces, projects, statuses, labels, tasks and comments, a board with drag and drop, a task detail panel, and live sync between two browser tabs. No agents yet: the CLI and agent identity are M2, cursors and animation M3. Everything is built test first.

**Decided (Lucas, 2026-11-14):** statuses belong to the workspace and are shared by its projects, so the All projects board lines up with no mapping.

## Conventions

- **Ids:** ULIDs as text. Humans and agents use task keys (`THAI-12`).
- **Times:** integer milliseconds since the epoch (UTC). Due dates are calendar days as `YYYY-MM-DD` text.
- **Booleans:** integer 0 or 1.
- **Nothing is hard-deleted** in M1. Rows get `archived_at` (or `deleted_at` for comments).
- **Positions:** fractional-index strings from the `fractional-indexing` package, wrapped once in `packages/domain/src/position.ts`. Task positions are ordered within (project, status). Status positions are ordered within the workspace.
- **Storage failures are defects**, not API errors (`Effect.orDie` at the service edge). API errors are only the tagged errors below.
- **Pinned versions:** Bun 1.4.4 (`.bun-version`), Effect 4.1.4 for `effect`, `@effect/platform-bun`, `@effect/sql-sqlite-bun`, `@effect/atom-react`, `@effect/vitest`. UI SDK 0.1.0-beta.2, Motion 14.14.0, React 19.3.1, Vite 8.3.8, Tailwind 4.3.5.

## Schema (M1 tables)

`?` marks a nullable column. Every table has `created_at`; mutable tables also have `updated_at`.

| Table | Columns | Constraints and notes |
| --- | --- | --- |
| `actors` | `id`, `kind` (`human` \| `agent`), `name`, `client?`, `color` | One human row, seeded on first start |
| `agent_sessions` | `id`, `actor_id`, `external_id?`, `client_name`, `entrypoint?`, `cwd?`, `project_id?`, `pid?`, `identity_json`, `started_at`, `last_seen_at`, `ended_at?` | `UNIQUE(external_id)`. Created in M1 so events can reference it; filled from M2 |
| `workspaces` | `id`, `name`, `slug`, `position`, `archived_at?` | `UNIQUE(slug)` |
| `projects` | `id`, `workspace_id`, `name`, `key`, `color`, `description`, `next_task_number` (default 1), `archived_at?` | `UNIQUE(key)` globally, so a bare `THAI-12` resolves. Key: `^[A-Z][A-Z0-9]{1,9}$` |
| `project_repos` | `id`, `project_id`, `path`, `git_remote?`, `is_main` | `UNIQUE(path)`. One `is_main` per project |
| `statuses` | `id`, `workspace_id`, `name`, `category`, `position`, `color`, `hidden` | `category` in backlog, unstarted, started, completed, canceled. `UNIQUE(workspace_id, name)` |
| `labels` | `id`, `workspace_id`, `name`, `color`, `archived_at?` | `UNIQUE(workspace_id, name)` |
| `tasks` | `id`, `project_id`, `number`, `title`, `description` (default `''`), `status_id`, `priority` (0–4, default 0), `position`, `due_date?`, `parent_id?`, `assignee_actor_id?`, `assignee_session_id?`, `created_by_actor_id`, `created_by_session_id?`, `version` (default 1), `archived_at?` | `UNIQUE(project_id, number)`. Index `(project_id, status_id, position)`. Priority: 0 none, 1 urgent, 2 high, 3 medium, 4 low |
| `task_labels` | `task_id`, `label_id` | Primary key on both |
| `comments` | `id`, `task_id`, `body`, `actor_id`, `session_id?`, `deleted_at?` | Index `(task_id, created_at)` |
| `events` | `seq` (integer primary key, autoincrement), `ts`, `type`, `entity_type`, `entity_id`, `workspace_id`, `project_id?`, `command_id`, `actor_id`, `session_id?`, `schema_version`, `payload` (JSON) | Indexes `(entity_id, seq)`, `(project_id, seq)`, `(command_id)` |
| `command_receipts` | `command_id` (primary key), `rpc`, `result` (JSON), `last_seq?` | Kept forever in M1; pruning later |

**Rules**

- **Task numbers:** `UPDATE projects SET next_task_number = next_task_number + 1 WHERE id = ? RETURNING next_task_number - 1`, inside the create transaction. Numbers are never reused, even after archiving.
- **`tasks.version`** goes up by one on every change to the task (fields, move, labels, archive).
- **Migrations** live in `apps/server/src/persistence/migrations/NNNN_name.ts`, run in order at startup and tracked in a `migrations` table.

**First start** (idempotent: running it twice changes nothing):

- the human actor, named from `git config user.name`, falling back to "Human"
- a "Personal" workspace
- statuses Backlog (backlog, hidden), Todo (unstarted), In Progress (started), In Review (started), Done (completed), Canceled (canceled, hidden)

## RPCs

Every write RPC carries a client-made `commandId`. It returns `{ result, seq }`, where `seq` is the highest event it committed, or `null` for no change. A repeated `commandId` returns the stored receipt and writes nothing.

| RPC | Payload | Success | Errors |
| --- | --- | --- | --- |
| `snapshot.get` | `{ scope? }` (none: the first non-archived workspace by position) | `{ seq, actors, workspaces, projects, statuses, labels, tasks }`; `workspaces` always lists every non-archived workspace, for the switcher | `NotFound` |
| `events.subscribe` (stream) | `{ scope, afterSeq }` | `CelloEvent` | `SnapshotRequired` |
| `workspace.create` | `{ name }` | workspace | `Invalid` |
| `workspace.update` | `{ id, name? }` | workspace | `NotFound`, `Invalid` |
| `project.create` | `{ workspaceId, name, key, color?, repoPath? }` | project | `KeyTaken`, `Invalid`, `NotFound` |
| `project.update` | `{ id, name?, color?, description? }` | project | `NotFound`, `Invalid` |
| `project.archive` | `{ id }` | project | `NotFound` |
| `status.update` | `{ id, name?, color?, hidden?, before?, after? }` | status | `NotFound`, `Invalid` |
| `label.create` | `{ workspaceId, name, color }` | label | `Invalid` (name taken) |
| `label.update` | `{ id, name?, color? }` | label | `NotFound`, `Invalid` |
| `label.archive` | `{ id }` | label | `NotFound` |
| `task.create` | `{ projectId, title, description?, statusId?, priority?, labelIds?, dueDate?, parentId?, before?, after? }` | task | `NotFound`, `Invalid` |
| `task.update` | `{ id, expectedVersion, title?, description?, priority?, dueDate?, parentId? }` | task | `NotFound`, `VersionConflict`, `Invalid` |
| `task.move` | `{ id, expectedVersion?, statusId, before?, after? }` | task | `NotFound`, `VersionConflict` |
| `task.setLabels` | `{ id, add, remove }` | task | `NotFound` |
| `task.archive` / `task.unarchive` | `{ id }` | task | `NotFound` |
| `task.history` | `{ id }` | events for that task | `NotFound` |
| `comment.list` | `{ taskId }` | comments | `NotFound` |
| `comment.add` | `{ taskId, body }` | comment | `NotFound`, `Invalid` |
| `comment.edit` | `{ id, body }` | comment | `NotFound`, `Invalid` |
| `comment.delete` | `{ id }` | comment | `NotFound` |

`scope` is `{ workspaceId }` or `{ projectId }`. `before` and `after` are neighbor task (or status) ids; the server computes the position between them.

**Errors** (tagged, in `packages/contract/errors.ts`):

- `NotFound { entity, id }`
- `Invalid { field, reason }`
- `KeyTaken { key }`
- `VersionConflict { entity, id, currentVersion, changedBy }`: `changedBy` is the actor name, for "changed by Claude since you opened it"
- `SnapshotRequired { latestSeq }`

## Events

Every event has the same envelope: `seq`, `ts`, `type`, `commandId`, `actorId`, `sessionId?`, `workspaceId`, `projectId?`, `schemaVersion` (1 in M1). `before` and `after` hold only the fields that changed.

| Type | Payload |
| --- | --- |
| `workspace.created` | `{ workspace }` |
| `workspace.updated` | `{ id, before, after }` |
| `project.created` | `{ project }` |
| `project.updated` | `{ id, before, after }` |
| `project.archived` | `{ id }` |
| `status.updated` | `{ id, before, after }` |
| `label.created` | `{ label }` |
| `label.updated` | `{ id, before, after }` |
| `label.archived` | `{ id }` |
| `task.created` | `{ task, labelIds }` |
| `task.updated` | `{ id, before, after, version }` |
| `task.moved` | `{ id, from: { statusId, position }, to: { statusId, position }, version, task }` (full row after, so any scope can upsert) |
| `task.labels_changed` | `{ id, added, removed, version }` |
| `task.archived` / `task.unarchived` | `{ id, version }` |
| `comment.added` | `{ comment }` |
| `comment.edited` | `{ id, before, after }` |
| `comment.deleted` | `{ id }` |

**Which events a subscription gets:** a workspace scope gets every event with that `workspaceId`. A project scope gets events with that `projectId`, plus workspace-level events (no `projectId`). Moving a task between projects is out of M1; `project_id` is fixed at creation until then.

**Event schema changes:** the payload decoder for each `type` is a union over `schemaVersion`. Old versions are upgraded to the current shape when decoded. An unknown version is a defect, so it fails loudly.

## Code layout

```
apps/server/src/
├─ main.ts                    # server entry: lock, migrations, seed, HTTP + /rpc
├─ caller/                    # CallerMiddleware → Caller (browser and headerless = human)
├─ events/                    # EventStore (append in tx), EventLog (PubSub + subscribe handoff), scope filter
├─ commands/                  # command receipts, commandId handling shared by all writes
├─ workspace/  project/  status/  label/  task/  comment/
│                             # each: <X>Service.ts + <X>Service.test.ts (+ <X>Decider.ts where useful)
├─ persistence/               # Sqlite layer, migrations/, seed
└─ rpc/                       # handlers: decode, call one service method, map errors

packages/contract/src/        # schemas, rpcs.ts, events.ts, errors.ts (kept from spike d)
packages/client/src/          # client.ts, sync/applyEvents.ts, sync/board.ts (atoms), commands/ (optimistic)
packages/domain/src/          # position.ts, taskKey.ts, color.ts (each with tests)
apps/web/src/
├─ app/                       # shell: sidebar, breadcrumb, tabs, routes
├─ board/                     # Board, Column, Card (from spike b), inline create
├─ task/                      # TaskPanel, PropertyFields, Comments, History
├─ project/                   # NewProjectDialog
├─ settings/                  # statuses and labels
└─ components/ui/             # primitives over UI SDK; own their look through variants
```

## Screens in M1

- **App shell:**
  - The sidebar lists projects and has a "New project" button.
  - The workspace switcher appears only once there are two workspaces.
  - A breadcrumb sits at the top.
  - Project tabs: Overview (stub: name, description, repo path, task counts), Issues, Docs ("coming in v1.1"), Activity ("coming in M3").
- **New project dialog:**
  - Fields: name, key (suggested from the name, checked as you type), color, optional repo path.
  - A duplicate key shows "THAI is used by ThaiLookup".
- **Board:**
  - Columns come from the visible statuses, each with a count and a `+`.
  - The `+` creates a task inline (type the title, Enter).
  - Hidden statuses fold into a strip on the right; click one to show it.
  - Cards show the key, status icon and title, priority bars, due date, labels and created date.
  - Drag and drop with the mouse and keyboard, applied optimistically.
- **Task panel:**
  - Opens beside the board at `/:projectKey/:number`; the route survives a reload.
  - Fields: title and description (markdown textarea with preview), status, priority, labels, due date, parent.
  - Below them: comments (add, edit, delete) and a plain history list from `task.history`.
- **Settings:**
  - Statuses: rename, recolor, reorder, hide.
  - Labels: create, rename, recolor, archive.
- **Live sync:** a change in one tab shows in another without a reload.
- **Themes:** light and dark.
- **Installable (PWA):** a web app manifest with name, icons and `display: standalone`, so Chrome's "Install app" gives Cello its own window and dock icon. The full Electron app comes after v1.

Not in M1: CLI and agent identity (M2), cursors and animations (M3), list layout and search (M3), docs and pages (v1.1).

## Tests in M1 (written first)

**Unit, next to the code**

1. `task.create` gives numbers 1, 2, 3 per project, and a number is never reused after archiving.
2. `task.create` writes the task and exactly one `task.created` event in one transaction. A failure in the middle leaves neither.
3. `task.move` places the card between its neighbors, at the top, at the bottom, and into an empty column.
4. `task.update` with a stale `expectedVersion` fails with `VersionConflict` naming who changed it.
5. Running the same `commandId` twice returns the stored result and writes no second event.
6. Project keys: pattern, uniqueness across workspaces, `KeyTaken`.
7. `applyEvents` skips events at or below the state's `seq`, keeps unchanged rows as the same objects, and applies a batch in order.
8. `position.ts`: between, before first, after last, and 1,000 random inserts stay ordered.
9. Event decoding: a v1 payload decodes; an unknown `schemaVersion` fails.
10. Caller: a browser connection and a headerless request both resolve to the human actor.

**Integration (`apps/server/test/integration/`)**

11. Two clients: A creates a task, B receives the event. B reconnects from its last `seq` and gets what it missed.
12. More than 5,000 missed events: `SnapshotRequired`, then the client takes a fresh snapshot and carries on.
13. Events committed while a subscriber is replaying are neither lost nor duplicated.
14. An optimistic move the server refuses (`VersionConflict`) rolls back in the client's state.
15. First start seeds once. A restart against the same database adds nothing.
16. Starting a second server against the same data folder: it doesn't open the database and reports the running one.

**End to end (`e2e/`, with videos)**

17. Drag a card in tab 1; it moves in tab 2.
18. Create a task with a column's `+`, edit it in the panel, add a comment, reload: everything is still there.
19. Move a card with the keyboard; the move survives a reload.

## Dev setup

- `bun install` at the repo root (Bun workspaces).
- `bun run dev` starts the server on port 4748 with data in `<worktree>/.cello/`, plus Vite on 5199, which proxies `/rpc` to the server. Dev never touches `~/.cello/`.
- `bun run test`, `bun run test:e2e` and `bun run check:changed` as in SPEC.md.
- Production: `cello start` serves the built web app itself on 4747. `bun build --compile` embeds `apps/web/dist`. The first M1 task checks that embedding works, using Bun's embedded files.
